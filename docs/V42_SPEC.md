## 2. 游戏概述

- **类型**：iPhone Safari 竖屏（390×844 pt 为基准）的第三人称小岛生活 + 打水漂小游戏，同时在桌面浏览器（WASD/鼠标）可玩。
- **玩家做什么**：控制可爱的小男孩在热带小岛上走、跑、涉水、坐、躺、睡、晒太阳；走到码头尽头扔石头打水漂，刷弹跳数和距离纪录；白天/夜晚切换。
- **不做的事**：不加新玩法模式（U-83）。重建 = 把现有内容用干净的底层重做，**不增不减**，再按 3A 线打磨。
- **技术前提**：Godot 4.7.2、`gl_compatibility` 渲染器、单线程 Web 导出（无 SharedArrayBuffer）、GitHub Pages 的 `docs/game_vN/`；纹理**不用** VRAM 压缩；物理 60 Hz。
- **发布**：新版本放 `docs/game_v42/`，`docs/index.html` 不动（仍是 v35），等你真机确认。

### 4.3 动画系统要求
- 一棵干净的 **AnimationTree**：移动层用 BlendSpace1D（idle–walk–run，按速度），行为层用状态机（移动 / 坐 / 躺 / 睡 / 投掷 / 庆祝），状态之间用交叉淡化，没有"每帧叠加 `_pose_add`"这类手写姿势补丁。

## 5. 操控与镜头

### 5.1 输入（U-32、U-40、U-41）
- **触摸只读 `InputEventScreenTouch/ScreenDrag`**（不用鼠标模拟）；多点触控按手指 id 分工：
  - 左下**虚拟摇杆**（基准位置约 (54,754) pt，半径适配 390 pt 屏宽，不挡安全区）；
  - 屏幕其它位置**单指拖动 = 转视角**；
  - 观景模式双指捏合缩放；
  - 摇杆手指与镜头手指永不抢事件。
- 摇杆手感（沿用 v40 调好的**起始数值**，重建后再用真机微调）：死区 6%（半径）；超过死区后幅度 `pow((m−0.06)/0.94, 0.85)`；**推到底就跑**（原始幅度 ≥0.90 进跑、≤0.82 退跑）；加速平滑时间 0.70 s、刹车 0.16 s；转向最大 7.5 rad/s 缓动；松手后 0.28 s 内停下。走速 ≈1.15 m/s，跑速 ≈2.7 m/s。
- 桌面：WASD/方向键走，Shift 跑，鼠标拖动转视角，滚轮缩放，空格投掷。
- 按钮（中文，右上角竖排）：**观景 / 固定视角 / 声音：开|关 / 夜晚|白天**；情境按钮：**打水漂、离开码头、坐下、躺下、睡觉、晒太阳、起来、返回**；投掷 UI 的**仰角 / 倾角**滑条、姿势：**站立|半蹲**。点击目标不小于 44 pt。

### 5.2 镜头模式
| 模式 | 行为 |
|---|---|
| **跟随（默认）** | 在人物后上方，默认俯角约 30–40°（旧版仅 16–21°；参考图 55–65° 更高；**见 §14 待定项**）；镜头位置临界阻尼跟随；摇杆按住时镜头偏航缓慢跟随移动方向；松手 ≤0.8 s 拉到宽景（臂长约 8.8 m）；上坡时随坡度抬升，保证"镜头到脚"的视线在地形之上。 |

- 镜头永不进入任何几何体内部，近裁剪面永不切到物体。

### 5.4 镜头碰撞与遮挡——**简明规则**（U-34 + U-35，核心要求）

这是本次重建要彻底改掉的东西。旧版用一个"屏幕空间 dither 切除胶囊"着色器，按**世界坐标**扔掉任何落在"镜头→人物射线管 + 人物周围 3 m"里的片元，而且岛上静态物体合并成少数几个网格共享同一个材质（见 §13），所以一堆本来没遮人的物体也被"挖洞"。新规则：

1. **镜头臂碰撞（拉近）**：镜头在 `SpringArm3D`/球形 `ShapeCast3D`（半径 0.25 m）上，从人物胸口朝期望机位投射，**只和"镜头阻挡层"碰撞**：地形、小屋、灯塔、礁石、树干（胶囊）、码头本体。碰到就**拉近**（拉近 ≤0.08 s，放远 ≈0.6 s 缓慢），镜头与任何表面至少 0.25 m。拉到比最小臂长（暂定 2.2 m）更近时，**优先抬高俯角**绕过障碍，而不是继续贴脸。
2. **小道具不挡镜头**：木桶、木箱、灯柱、路牌、长椅、木头、火把、水桶**不在**镜头阻挡层，镜头不会为它们拉近。
3. **遮挡淡化（只管"挡住人的那几个物体"）**：每帧用 **5 条射线**（头顶、胸、髋、两只脚）从镜头射向人物；**同一个物体被 ≥2 条射线打中**，才算"遮挡物"。遮挡物**整体**淡到不低于 **35%**（淡入 0.2 s、淡出 0.35 s）。每个物体用**自己的** 0..1 淡化参数（`instance uniform` 或独立材质），**与世界坐标、屏幕位置无关**。
4. **绝不允许**：丢弃（discard）整件物体或其中一块；用硬平面把物体切掉；淡到 0；按距离人物的球/管体去"挖洞"；让不在镜头→人物视线上的物体（人物身后、身旁的东西）有任何变化。
5. **叶片卡片**（灌木、棕榈叶）：属于"被遮挡时整体淡到 35%"的同一规则，不是 dither 挖洞；叶片弯折（风）不得依赖相机位置。
6. **静态合并网格必须按"可被淡化的物体"拆开**：每个可能挡人的物体（每棵树、每丛灌木、每个桶/箱）要有自己的 `GeometryInstance3D`（或 MultiMesh 的 per-instance 参数），否则无法单独淡化——这是架构硬约束。
7. 提供 `?occ=0` 关闭遮挡逻辑，用于开/关对比图和"凭空消失"回归。

- 与用户交流的消息一律中文（U-75，对话层规则，不属于游戏内）。

## 11. 验收清单（可测量；**每个版本发布前逐条出证据**）

**总原则**：
1. 所有测量都在**导出的网页版**上做（Chromium iPhone 13 档案 390×844，dpr 3，SwiftShader 或真机），测的是**屏幕上真正画出来的姿势**；编辑器里的骨骼数字不算。（教训：旧版 IK 写了网页端不画的通道，测试全绿，画面埋腿。）
2. 凡是数值和图片矛盾，**以图片为准，并修测试**，不许改人物去追数字，也不许放宽阈值或跳过帧来过关。
3. SwiftShader 走不了 100 m（CDP 里 HUD 说 1.7 m/s、身体几乎不动），所以长路线测试用 **headless Godot 跑同一份控制器代码**，固定 60 Hz；CDP 真触摸只做短程（拖动三连拍、首步响应）。真机性能数据以你贴的 `复制数据` 为准。

## 12. 重建架构

### 12.1 总原则
- **一个地面真相**：渲染网格 == 步行碰撞。地形/码头/台阶/坡道由**同一份顶点+索引数组**同时生成 `MeshInstance3D` 和 `StaticBody3D`（`ConcavePolygonShape3D`）。没有解析高度函数、没有双线性采样、没有"海床兜底"、没有 `DOCK_LIP_RAMP` 之类的假表面。需要预先布局（路径、垫平的木头位置、码头）时，用纯数据函数一次性烘焙进网格，之后所有人（脚、相机、脚印、脚步声）都查碰撞世界。
- **一个根的所有者**：人物根位置只由 `PlayerBody`（`CharacterBody3D`）在 `_physics_process` 中写；显示插值是**单一模块**，且只做 XZ+Y 的渲染插值，不再重新采样地面。
- **一个姿势的所有者**：骨架姿势 = AnimationTree 输出 → 脚部 IK 修饰器 → 渲染。**不再**有 `_pose_add` 叠加、`SOLE_NUDGE`、`FLOOR_OFFSET`、`_contact_lift`、骨盆 hack 之类的偏移常量。
- **模块小**：每个脚本 ≤ 400 行（硬上限 600）；旧版 `main.gd` 7.5k、`boy.gd` 2.9k、`island.gd` 3k 的结构不能重现。
- **可测试**：每个模块都有 headless 单测；测试工具和游戏用**同一份**控制器/地面/IK 代码。

### 12.3 每帧顺序（固定，写成注释放在 `game.gd` 顶部）
1. `_physics_process`（60 Hz）：输入 → `PlayerBody` 目标速度（加减速曲线）→ `move_and_slide()` 在 `Ground` 上（`floor_snap_length`、最大坡度、台阶高度明确设定）→ 状态机（移动/坐/睡/投掷）。
2. 渲染帧：显示根 = 物理根插值（`Engine.get_physics_interpolation_fraction()`）→ **AnimationTree** 更新 → **脚部 IK（SkeletonModifier3D）**（在蒙皮之前）→ 相机枢轴跟随显示根 → `camera_rig` 臂碰撞 → `occluder_fader` → 脚印/脚步事件。
3. 任何模块**禁止**自己再去采样地面高度来改人物 Y；只能读 `PlayerBody` 提供的接触信息。

### 12.4 脚部 IK（**站立相** IK，U-20–23 的核心）
- 使用 Godot 4.7.2 内置的 `TwoBoneIK3D`（`SkeletonModifier3D` 体系）或自写的同类修饰器；**不得使用 `set_bone_global_pose_override`**（旧审计：网页 Compatibility 蒙皮路径不画这个通道，数字全绿画面埋腿）。构建后第一件事：在**导出的网页版**验证 IK 结果确实被画出来（A-2 的刻度图）。
- **接触曲线**：用 FK 离线分析每个移动剪辑（walk/run/turn/idle）的脚高度与速度，烘出"左/右脚站立权重 0..1"曲线（资源文件），IK 权重跟着曲线走。站立相：把**踩地脚的鞋底点**钉在落脚那一刻的地面位置（不滑步），摆动相：IK 权重→0，只保证不入地。
- **目标高度**：对踩地脚在 **脚跟、脚尖** 两点向下射线（查 `Ground` 碰撞），取各自命中点；脚掌旋转对齐法线（限制 ≤25°）；**鞋底到踝骨的偏移用实测值**（旧经验：蒙皮顶点比鞋底高 3.2 cm，ankle→sole 12.2 cm——必须量鞋底外底网格的最低点，别拿蒙皮顶点当鞋底）。
- **骨盆**：只下降"较短的那条腿需要的量"，上限 8 cm，二阶阻尼平滑（≈0.1 s）；上坡时不抬骨盆（抬由根的位置管）。
- **铁律**：**不许把腿"瞄向一个独立的探针面"**（v39 `5bfc309` 就是这样把小腿压进地里的）；IK 目标只来自 `Ground` 射线，且不得与根高度写入两套逻辑。
- **测量用的鞋底点**：在左右脚骨上挂 4 个 `BoneAttachment3D` 标记（脚跟/脚尖/内/外），位置取自鞋底外底最低顶点；测试工具读这些标记，并用 A-2 的正交图交叉验证。

### 12.5 相机装置
- `CameraRig`：枢轴（跟随显示根，胸口高度，临界阻尼）→ 臂（球形 `ShapeCast3D`，只碰"镜头阻挡层"，见 §5.4）→ `Camera3D`，近裁剪面 0.05–0.1 m。
- 模式用小状态机（跟随/观景/固定/休息/投掷）+ 0.35 s 缓动混合；休息机位由各 `interactable` 提供一个 `Marker3D`，不在相机脚本里硬编码。
- `OccluderFader`：每个物体一个 `Fadable`（组件），5 射线判断，见 §5.4；只写该物体自己的淡化参数。
- 取景保证：枢轴目标=胸口加前瞻；偏航跟随在摇杆按住时缓慢进行，松手后按 0.8 s 展开。

### 12.6 输入
- 单一 `touch_router.gd` 收 `InputEventScreenTouch/Drag`，按手指 id 分配给摇杆/转镜头/投掷划动/捏合；其它模块不直接读触摸；不依赖 `emulate_mouse_from_touch`。

### 12.7 资源与导出
- 导出模板：单线程 Web，`vram_texture_compression=false`，自定义中文加载页（`web/shell.html`），`head_include` 保留 iOS 音频解锁和安全区脚本，注销旧 Service Worker，COI SW 关闭。
- 纹理：全部无损/JPEG 导入；男孩脸部表情改"脸部小图集"；字体子集脚本；`.pck` 过滤规则只放进运行时需要的文件。
- 构建脚本 `tools/export.sh` 一键：字体检查 → 导出 → 跑门槛测试（A-5 拖动三连拍、A-6、O-1）→ 把 PNG 存进 `screenshots/vN/`。

## 13. 已知的坑（只作教训，不是需求）

出处：`docs/ARCHITECTURE_AUDIT.md`、`V37–V41` 报告、`AAA_BAR.md`、云端程序员记录。

1. **下沉的起点**：v39 提交 `5bfc309` 把脚部 IK 换成"把腿瞄向一个探针面"，之后每个提交都保留了"探针驱动的姿势"→ 小腿被压进地里、HUD 却显示 gnd 0.8 cm。恢复 v38 的地面/根/IK（`05d8952`）后恢复正常。（所以：**IK 目标只能来自与根相同的 `Ground`，不能另起一个探针。**）
2. **网页端不画 `bone_global_pose_override`**：编辑器里测的数字与网页上看到的画面是两回事；要以导出网页版的实图为准。
3. **同一帧里高度被写多次**（物理里写一次、显示插值里再采样一次、相机又在 IK 之前跑）→ 阶梯状抖动、阴影与鞋错位。重建规定了单一所有者（§12.3）。
4. **旧遮挡着色器**（`shaders/cutout.gdshaderinc` 等）：按世界坐标判断"在镜头→人物射线管（半径 1.5–2.2 m，最宽 ×1.45）内，或距身体胶囊 0.92 m 内就丢弃片元"，核心区"硬打开"，射线末端之后甚至对**人物周围的球体**起作用。静态物体合并成少数网格共享材质（`SB`、`FB`），所以桶、灯、路牌、屋墙、码头板会一起被"挖洞"，而且视觉上是"整块消失"。**这很可能是你看到物体消失的原因之一**（我没看到截图，仅按代码判断）。重建用 §5.4 的"每物体淡化、不丢弃、不低于 35%"替换。
5. **测试陷阱**：SwiftShader 走不到 100 m；测试脚本直接推位置抓不到触摸路径问题；旧脚本测的是"踝骨 − 一个垫高值"，而鞋底外底比蒙皮顶点还低 3.2 cm；测"蒙皮顶点 vs 碰撞三角面"在站立相出现过 77% 假"浮空"。→ 用正交刻度图作为真值，测试的"鞋底点"必须取鞋底外底。
6. **双线性高度 ≠ 渲染三角形**（v36 的根因）；码头唇 1.45 m 的插值是假表面。
7. **VRAM 压缩纹理 + 物理插值开关 + 触摸转鼠标丢失**让 v27 在 iPhone 打不开；包体 >40 MB 在上海 LTE 卡死。
8. **图元预算**：地形加密到 213k 图元（v32）、小屋视角 116k（v41）都超预算；男孩单个模型就 47k 三角。
9. **字体子集漏字**出过两次（固定视角、复制数据、Δ）。
10. **120 Hz 屏**：物理 60 Hz 与渲染 120 Hz 不同步时，没有渲染插值就抖；旧测试里 120 fps 下人物位移 max/median=44。
11. **"静音提示条"**挡住左上角 HUD（旧截图可见）；调试面板曾遮标题。
12. 旧 `AAA_BAR.md` 里 "≈100k 图元" 与你后来说的 "≈110k" 不一致，这里采用 **≤110k**。
